# 任务第 1 部分：加入人物公开资料

> Task: *search online for public information about both people and add it to their prompts to make them more realistic. In your report, list which facts you added for each person and where they came from. And how you fetch those data and list the source.*

相关文件：

| 文件 | 内容 |
|---|---|
| `experiments/bezos_graham/personas/bezos.txt` | 加入买方 prompt 的 Bezos 资料（英文，模型实际看到的原文） |
| `experiments/bezos_graham/personas/graham.txt` | 加入卖方 prompt 的 Graham 资料 |
| `experiments/bezos_graham/personas/sources.csv` | 脚本自动生成的结构化来源表：事实、核对状态、来源、网址、下载时间、SHA-256、原文摘录 |
| `experiments/bezos_graham/personas/facts_spec.csv` | 事实清单：每条事实的英文原句、来源、核对关键词（人工挑选的唯一来源） |

## 1. 资料是怎么获取的

分两步：先**检索**找到合适的来源，再用脚本 **`experiments/bezos_graham/fetch_public_facts.py` 自动下载并逐条核对**。

### 1.1 检索与挑选来源

用网络搜索查两人的生平、2013 年《华盛顿邮报》出售时的公开声明、The Washington Post Company 的财报。挑选来源时优先一手资料：

- 财务数据：SEC EDGAR 上 **The Washington Post Company 2012 年 Form 10-K**（一手、经审计）；
- Bezos 的经营理念：SEC 上的 **Amazon 股东信**（附 1997 年原信）；
- Graham 对报纸处境的看法：2013 年 8 月 5 日 Poynter 报道中**逐字引用的 Graham 致员工声明**和公司新闻稿；
- 生平履历：Wikipedia（二手来源，但都是广泛公开、容易核实的基本事实）。

### 1.2 从原始资料到 prompt 的完整流程（可复现）

```
personas/facts_spec.csv        人工挑选：要加哪些事实、写进 prompt 的英文原句、在原文里用来核对的关键词
        │
        ▼  fetch_public_facts.py：下载来源原文 → 保存快照 → 逐条核对
personas/evidence/             原文快照（snapshots/）、下载记录（fetch_log.json）、证据报告（evidence_report.csv/.md）
        │
        ▼  同一脚本自动生成
personas/sources.csv           结构化来源表：事实、核对状态、来源标题与网址、下载时间、SHA-256、获取方式、原文摘录
        │
        ▼  build_personas.py：只用核对通过（verified）的事实
personas/bezos.txt、graham.txt  模型实际读到的人物资料
```

运行（在仓库根目录）：

```powershell
python experiments/bezos_graham/fetch_public_facts.py --email 你的邮箱    # 联网：下载 + 核对 + 生成 sources.csv
python experiments/bezos_graham/fetch_public_facts.py --offline            # 不联网：用已保存的快照重新核对
python experiments/bezos_graham/build_personas.py                          # 由 CSV 生成 bezos.txt / graham.txt
```

细节：

1. **下载原文**：Wikipedia 用官方的 `action=raw` 接口取页面源文本；SEC 文件和新闻网页直接下载 HTML。SEC EDGAR 要求在 User-Agent 中留联系邮箱，所以有 `--email` 参数。每个来源的正文保存在 `personas/evidence/snapshots/`，下载时间、HTTP 状态码、SHA-256 指纹记在 `snapshots/fetch_log.json`。
2. **逐条核对**：`facts_spec.csv` 里为每条事实列出若干关键词或关键句，必须**全部**在对应来源原文中找到，才算 `verified`。
3. **生成 CSV**：核对结果写入 `sources.csv`，每条事实附一段原文摘录作为证据。
4. **生成 prompt 文本**：`build_personas.py` 只把 `include_in_prompt = yes` 且核对通过的事实写进 `bezos.txt` / `graham.txt`，每行一条事实，可以和 `sources.csv` 逐行对应。单元测试会检查仓库里的这两个文件与 CSV 重新生成的结果完全一致，并检查真实成交价（X1）没有出现在任何 prompt 里。

2026-10-15 的运行结果：**18/18 条事实全部在来源原文中找到**。其中 CNN 页面返回 HTTP 503（服务器端故障），X1 这一条自动改用 Poynter 报道核对：该报道同样写明 "The purchase price is $250 million"。

在国内网络环境下，Wikipedia 或 SEC 可能无法访问。这时用 `--offline` 即可，它会基于仓库里已保存的快照重新核对。

## 3. 设计上的几个决定（报告里可直接引用）

1. **时间点统一在 2013 年年中、交易发生前**：模拟的是“正在谈判”，所以只放谈判时双方已经知道的公开信息。
2. **刻意不放真实成交价**：现实中 Bezos 以 2.5 亿美元现金买下（[CNN Money](https://money.cnn.com/2013/08/05/news/companies/washington-post-bezos)）。如果把这个数字写进 prompt，双方会直接锚定历史答案，谈判就失去意义，所以不加入。`sources.csv` 里把它列为 X1“有意排除”。
3. **不放任何秘密底价**：人物资料里没有 350、200 或卖方初始要价 400，不破坏不完全信息设定（单元测试会检查）。
4. **财务事实双方都给**：《邮报》的年报是公开信息，买卖双方都能看到，所以两边放同一段。
5. **“个人身份收购”写给买方**：基线实验里 Bezos 反复编造“与 Amazon 平台的协同效应”，这条事实用来纠正这种幻觉。
6. **只改资料、不改策略**：资料里只陈述事实，不包含“你应该压价”之类的谈判策略。策略属于任务第 2 部分，且只能改买方。
7. **插入位置**：资料放在 Table 14/15 模板最后一行 “Now, respond as …” 之前，模板原文一字不改。

## 4. 运行方式

成交规则保持论文原样（`price_tolerance = 0`，双方报价必须完全相同）。A0 组 = Table 14/15 原文 + 双方人物资料：

```powershell
python experiments/bezos_graham/run_experiments.py --runs 10 --tag A0_personas --quiet --backend gguf --model-path D:\models\Qwen3-4B-Instruct-2507-Q8_0.gguf --max-new-tokens 300 --personas
```

想先看模型实际收到的 prompt，可以跑一次：

```powershell
python experiments/bezos_graham/run_episode.py --backend gguf --model-path D:\models\Qwen3-4B-Instruct-2507-Q8_0.gguf --max-new-tokens 300 --personas --show-prompt
```

说明：第 1 部分按任务要求同时修改双方 prompt（"add it to their prompts"）；“只改买方”是第 2 部分的约束，见 `04_任务第2部分_买方prompt设计.md`。
