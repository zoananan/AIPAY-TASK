# 任务第 1 部分：加入人物公开资料

> Task: *search online for public information about both people and add it to their prompts to make them more realistic. In your report, list which facts you added for each person and where they came from. And how you fetch those data and list the source.*

论文没有“人物资料”这一环节（Table 14/15 里只有名字），所以“怎么选事实”是任务新增的部分，由我们自己设计。我们用的是**混合式自动流水线**：结构化数据库给生平，规则抽取财报数字，本地模型从文章里抽取，再用公开规则统一筛选。每条事实都附有证据，并且可以离线重新生成。

相关文件（都在 `experiments/bezos_graham/` 下）：

| 文件 | 内容 |
|---|---|
| `persona_pipeline.py` | 整个流水线：`fetch` / `extract` / `build` / `all` 四个子命令 |
| `personas/manual_facts.csv` | 人工补充条目（目前 2 条），每条要写理由，引用同样要逐字核对 |
| `personas/evidence/snapshots/` | 下载的原始资料快照，以及 `fetch_log.json`（网址、下载时间、HTTP 状态、SHA-256） |
| `personas/evidence/llm_extractions/` | 本地 Qwen 每个文本块的原始输出（附 prompt 指纹），保证离线可复现 |
| `personas/evidence/raw_candidates.csv` | `extract` 的输出：全部候选事实 |
| `personas/candidate_facts.csv` | `build` 的输出：每条候选事实的状态（selected / rejected）和原因，**报告用的完整审计表** |
| `personas/sources.csv` | 入选事实：陈述、获取方法、来源网址、下载时间、SHA-256、证据原文 |
| `personas/bezos.txt`、`personas/graham.txt` | 写进 prompt 的人物资料，由 `sources.csv` 自动渲染 |

旧版的 `fetch_public_facts.py`、`build_personas.py` 和 `facts_spec.csv` 是“人工列事实 + 脚本核对”的方案，已被本流水线取代，git 历史里仍可查到。

## 1. 资料是怎么获取的（how we fetch the data）

```
fetch    ──►  snapshots/            Wikidata SPARQL 结果(JSON) + Wikipedia 源文本 + SEC 文件 + Poynter 报道
                 │
extract  ──►  ① Wikidata 字段 → 句子模板          （生平：出生、父母、学历、任职、获奖、创办机构）
              ② 正则抽取 SEC 10-K                 （《邮报》收入、亏损、发行量）
              ③ 本地 Qwen 抽取 + 逐字引用核对       （Graham 的经历和观点、Bezos 的经营理念）
              ④ manual_facts.csv                  （人工补充，引用逐字核对）
                 │  每条候选先过“单条检查”
                 ▼
build    ──►  筛选规则（时间截止、结果黑名单、去重、数量上限）
              → candidate_facts.csv / sources.csv / bezos.txt / graham.txt
```

运行（在仓库根目录，VS Code 终端）：

```powershell
# 一次性完成（需要联网 + 本地模型；本地模型抽取在 CPU 上大约需要 10–30 分钟）
python experiments/bezos_graham/persona_pipeline.py all --email 你的邮箱 --backend gguf --model-path D:\models\Qwen3-4B-Instruct-2507-Q8_0.gguf

# 或分步运行
python experiments/bezos_graham/persona_pipeline.py fetch --email 你的邮箱
python experiments/bezos_graham/persona_pipeline.py extract --backend gguf --model-path D:\models\Qwen3-4B-Instruct-2507-Q8_0.gguf
python experiments/bezos_graham/persona_pipeline.py build

# 不联网：跳过 fetch，直接用仓库里的快照
# 不跑模型：extract --llm none，只用 ①②④，加上已缓存的模型输出
python experiments/bezos_graham/persona_pipeline.py extract --llm none
python experiments/bezos_graham/persona_pipeline.py build
```

### 1.2 四种抽取方法

1. **Wikidata + 句子模板**（确定性）。查询属性：出生日期 P569、出生地 P19、父母 P22/P25、学校 P69、雇主 P108、职位 P39、奖项 P166、成员资格 P463，以及“创办者 = 此人”（反查 P112，配合成立时间 P571）。每条结果按固定模板写成第二人称句子，例如 `From 1990 to 1994 you worked at D.E. Shaw.`；证据记成“实体网址#属性”。
2. **正则抽取 10-K**（确定性）。三个固定的句式或表格：报纸出版部门收入、营业亏损、平均付费发行量。
3. **本地 Qwen 抽取**。文章按约 5000 字符分块。模型用贪心解码（temperature 0），要求只返回 JSON 列表，每项包含 `statement`（第二人称一句话）、`quote`（从原文逐字复制 5–40 个词）、`year`、`category`。模型的原始输出按块存入 `llm_extractions/`，连同 prompt 的 SHA-256 指纹：之后只要原文和 prompt 不变，就直接读缓存，不必再跑模型，结果完全可复现。**模型的输出不直接采信**，必须通过下面的程序化检查。
4. **人工补充**（`manual_facts.csv`）。只用于自动方法覆盖不到、但实验设计需要的条目，每条都要写理由，引用同样逐字核对。目前只有两条：
   - **M1**：Bezos 以个人身份收购、Amazon 不参与（用于纠正基线实验中“与 Amazon 协同”的幻觉）。
   - **X1**：真实成交价 2.5 亿美元，作为“有意排除”的记录。

### 1.3 单条检查（模型抽取的事实必须全部通过）

| 检查 | 淘汰原因（写在 `candidate_facts.csv` 的 reason 列） |
|---|---|
| 引用在原文中逐字出现（忽略大小写、引号样式和空白） | `quote not found verbatim in source (possible hallucination)` |
| 陈述里的每个数字都出现在引用中 | `statement contains numbers not in quote` |
| 陈述和引用中没有晚于 2013 年的年份 | `rule: after cutoff` |
| 前 8 个词内有 you/your，且不超过 60 词 | `not in second person` / `too long` |
| 类别属于 background / education / career / philosophy / views_on_post | `category not allowed` |

### 1.4 筛选规则（build 阶段，对所有方法统一适用）

1. **时间截止 2013-07-31**：模拟的是交易前的谈判。没有日期的 Wikidata 条目也排除，因为无法判断它是否发生在截止日期之前。
2. **结果黑名单**：出现 `250 million`、`purchase price`、`sold`、`sale`、`Nash Holdings`、`Graham Holdings`（公司在 2013 年 11 月出售报纸后才改名）等词的条目一律排除，防止泄露真实交易结果。
3. **其他规则**：学历只保留大学或学院；职位没有注明所属机构的排除（例如只写 “chief executive officer”）；Wikidata 中没有英文名称的条目排除。
4. **去重**：两句话的词集合 Jaccard 相似度 ≥ 0.6 视为重复，按优先级保留：Wikidata > 正则 > 人工 > 模型。
5. **数量上限**：每人最多 12 条个人事实。

关于 Graham 观点的一个约定：Poynter 报道中 2013 年 8 月宣布交易时 Graham 对报纸处境的评价（收入连年下滑、成本削减已到极限等），我们视为他在谈判期间已经持有的看法，允许进入 prompt；但其中涉及“出售”或“新东家”的句子会被黑名单排除。

## 3. 设计上的几个决定（报告里可直接引用）

1. **时间点统一在 2013 年年中、交易发生前**：模拟的是“正在谈判”，所以只放谈判时双方已经知道的公开信息。
2. **刻意不放真实成交价**：现实中 Bezos 以 2.5 亿美元现金买下。如果把这个数字写进 prompt，双方会直接锚定历史答案，谈判就失去意义。`manual_facts.csv` 里把它记为 X1“有意排除”，结果黑名单也会拦截。
3. **模型只做“候选生成”，不做“裁决”**：模型抽取的每条事实都要附上逐字引用，再由程序核对。编造的引用、数字或年份对不上的条目都会被自动淘汰，所有淘汰原因都可以审计。
4. **不放任何秘密底价**：人物资料里没有 350、200 或卖方初始要价 400，不破坏不完全信息设定（单元测试会检查）。
5. **财务事实双方都给**：《邮报》的年报是公开信息，买卖双方都能看到。
6. **只改资料、不改策略**：资料里只陈述事实，不包含“你应该压价”之类的谈判策略。策略属于第 2 部分，且只能改买方。
7. **插入位置**：资料放在 Table 14/15 模板最后一行 “Now, respond as …” 之前，模板原文一字不改。
8. **最后一道人工审阅**：自动流水线跑完之后，人工通读 `bezos.txt` / `graham.txt`。如需调整，只能通过修改筛选规则或 `manual_facts.csv`（附理由）来实现，不直接手改输出文件。单元测试会检查这两个文件与 `sources.csv` 渲染的结果完全一致。
