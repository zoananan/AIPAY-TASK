## 2. 逐节对照表

### §3 Problem Settings（形式化定义）

| 论文 | 含义 | 代码位置 |
|---|---|---|
| 买方状态 $b_i$、卖方状态 $\sigma_j$（私有） | 买方最高支付价、卖方最低接受价 | `envs/single_buyer_product_seller/Task1_basic_price_negotiation.py` `reset()` L141–157：`buyer_context["max_price"]` 只给买方，`seller_context["min_price"]` 只给卖方；Agent 构造参数 `buyer_max_price` / `seller_min_price`（`buyer_agent.py` L22、`seller_agent.py` L21） |
| 商品表示 $v_j$（公开） | 商品属性与描述 | `reset(product_info=...)`，同时进入双方 context（L147、L152） |
| 市场上下文 $x$（公开） | 季节、平台等外部因素 | 环境构造参数 `environment_info`（L28、L80），双方 context 都有 |
| 对话历史 $h_{ij}^{(t)}$ | 截至第 t 轮的公开对话 | `memory/conversation_memory.py` `ConversationMemory`，每条为 `(role, content, round, metadata)`；环境在 `step()` L185/L194 写入 |
| 买方策略 $\pi_i^B(\cdot\mid b_i,v_j,x,h^{(t-1)})$ | 由 LLM 生成买方消息 | `BuyerAgent.respond()`（`buyer_agent.py` L38–195）：拼 prompt → `self.model.generate()` |
| 卖方策略 $\pi_j^S(\cdot\mid \sigma_j,v_j,x,h^{(t-1)})$ | 由 LLM 生成卖方消息 | `SellerAgent.respond()`（`seller_agent.py` L37–153） |
| 解析器 $\Pi$：$a^{(t)}=\Pi(m^{(t,B)},m^{(t,S)})$ | 自然语言 → 结构化报价 | `_extract_price()` L423–483：优先匹配 `### BUYER_PRICE($X) ###`，其次 `### $X ###`，最后退回文中任意 `$数字` |
| 终止条件：达成一致 / 超过最大轮数 | | `step()` L209–235：`_check_agreement()` → AGREED；`current_round >= max_rounds` → TIMEOUT |

### §4.4 Metrics 与 Algorithm 1

| Algorithm 1 行 | 代码（Task1 环境） |
|---|---|
| 1: $Z=p^{\max}-p^{\min}$ | L777 / L909 / L1020 |
| 2: $d=\gamma^{t-1}$ | L783–784：`round_index = current_round` —— **注意见第 3 节差异 ②** |
| 3: if $p^{\min}\le p\le p^{\max}$ | L815 `valid_range`，且要求 `feasible_deal`（已 AGREED） |
| 4–6: $r_b, r_s, Q=4r_br_s$ | L820–824 |
| 7: GlobalScore $=d(D+QW+E)$ | `_calculate_global_score()` L722–868 |
| 8: BuyerScore $=d(D+r_bW+E)$ | `_calculate_buyer_score()` L870–979 |
| 9: SellerScore $=d(D+r_sW+E)$ | `_calculate_seller_score()` L981–1090 |
| 11–12: 失败 $-F(1-d)$ | L853–854 等 |
| §5.1：D=30, W=55, E=15, F=15, γ=0.99 | 环境构造函数默认值 L31–43（买方/卖方分数各有一套同值参数） |

## 3. 论文与 `1a347cf` 代码不一致的地方（均已用测试验证）

测试见 `experiments/bezos_graham/tests/test_offline_pipeline.py`，运行方式：`python -m unittest discover -s experiments/bezos_graham/tests -v`

| # | 现象 | 影响 | 我们的处理 |
|---|---|---|---|
| ① | 轮数多一轮：`step()` 在**递增前**判断 `current_round >= max_rounds`，`max_rounds=20` 时实际可以谈 **21 轮** | 超时运行的“轮数”被记成 21；最多 42 次 LLM 调用 | 给环境传 `max_rounds-1`，使上限恰好 20 轮（可用 `--no-round-fix` 关闭）；测试 `test_round_cap_is_exactly_20` / `test_upstream_round_cap_without_fix_is_21` |
| ② | 折扣指数差一：成交后先 `current_round += 1` 再算分，实际用的是 $\gamma^{t}$ 而非论文的 $\gamma^{t-1}$ | 例：第 4 轮以 250 成交，论文公式 GlobalScore = 91.10，代码 = 90.19（最新 HEAD 已修正为 `current_round-1`） | 结果里同时保存上游分数和按 Algorithm 1 逐行实现的分数；测试 `test_upstream_discount_uses_gamma_power_t` |
| ③ | Table 15 有 “DEAL AGREEMENT INSTRUCTION / MAKE_DEAL”，`seller_agent.py` 里**没有** | 卖方 prompt 与论文表格不一致 | 我们的卖方模板逐字采用 Table 15 |
| ④ | `MAKE_DEAL` 在 Task1 环境里**完全不起作用**（只有部分多方环境检查它） | 只说 “MAKE_DEAL” 但报价不同，不会成交 | 保持上游规则，只在日志中记录 MAKE_DEAL 出现情况 |
| ⑤ | 上游第一句拼成 “You are Buyer, **You are** a buyer…” | 与 Table 14 文字不同 | 模板逐字采用 Table 14：“You are Buyer, a buyer…” |
| ⑥ | “Current Negotiation State” 直接打印整个 observation，其中又含一份完整对话历史（Python list 形式） | 对话历史在 prompt 里出现两次，prompt 长度约翻倍 | Table 14/15 中 `{current_state}` 与 `{conversation_history}` 是两个槽位，我们从 state 中去掉重复的历史 |
| ⑦ | `VLLMLLM.generate()` 把 prompt 当裸文本续写，**没有套聊天模板** | 对 Instruct 模型不合适 | 我们的适配器用 `apply_chat_template`（HF）或 `llm.chat()`（vLLM），与 API 后端一样作为一条 user 消息 |
| ⑧ | 环境默认 `price_tolerance=1.0`，示例配置是 `0.0` | 决定“差 1 是否算成交” | 用 `0.0`（论文 §4.1 “propose the same price”） |
| ⑨ | 解析器找不到标准标签时会抓文中最后一个 `$数字`，例如 “We are only $20 apart” 会被解析成报价 20 | 可能把非报价数字当报价 | 每条消息额外做格式审计（`tag_ok`），在结果中报告标签合规率；测试 `test_upstream_parser` |
| ⑩ | 成交判定不检查价格区间 | 买方可能“成交”在 360（超出上限 350） | 结果中单独给出 `deal_in_zone`；测试 `test_deal_outside_zone_is_flagged` |

## 5. 本任务实际走过的调用链

```
run_experiments.py / run_episode.py             ← 我们的入口（仿上游 examples/…/Task1_basic_price_negotiation.py）
  └─ build_model()        model_adapter.py      ← 新增：Qwen3-4B-Instruct-2507，本地离线，套聊天模板
  └─ build_agents()       paper_agents.py       ← 继承上游 BuyerAgent/SellerAgent，prompt 改为 Table 14/15 原文
  └─ create_env()         episode.py → 上游 make("Task1_basic_price_negotiation-v0")
  └─ env.reset()          上游：私有保留价分别注入双方 context
  └─ while not done:      上游示例主循环
        buyer.respond()   → model.generate()
        seller.respond()  → model.generate()
        env.step()        上游：_extract_price() → _check_agreement() → 评分
  └─ 保存 JSON/transcript/CSV，汇总平均成交价、成交率、平均轮数     ← 新增
```

具体每个文件做什么、哪些行是复用上游的，见 [`02_第一步代码讲解.md`](02_第一步代码讲解.md)。
