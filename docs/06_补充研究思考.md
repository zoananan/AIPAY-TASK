## 1. 1v1 的"最优解"：中间价是设计选择，不是理论结论

### 1.1 论文是否涉及

论文 §4.4 Score Design 说明了 GlobalScore 的设计：

> "GlobalScore uses a symmetric quality term Q = 4·rb·rs that peaks when surplus is split equally, while BuyerScore and SellerScore reward each party's individual surplus."

论文只说明 Q 在平分剩余时最大，没有解释为什么平分是好的结果，也没有和博弈论的议价解联系起来。正文没有出现 Nash bargaining solution 或 Rubinstein 模型的推导，这些文献只在相关工作中被引用（§2）。

### 1.2 我们的分析

1. **Q 就是归一化的纳什乘积。** 纳什议价解最大化双方收益的乘积 (u_b − d_b)(u_s − d_s)。以各自的保留价为谈判破裂点、收益与价格成线性时，乘积等于 rb·rs，Q = 4·rb·rs 只是把它缩放到 [0, 1]。所以"中间价最优"等价于"以对称纳什议价解为公平标准"。这是一个价值判断，论文没有点明。
2. **换模型或协议细节，理论预测会变。**
   - Rubinstein 无限期交替出价模型（完全信息）：先出价的一方得到 1/(1+δ) 的剩余。本实验每轮买方先说，若取 δ = 0.99（与论文的折扣因子相同），买方份额约 0.5025，对应价格约 274.6，非常接近中间价 275。也就是说，双方都很有耐心时，Rubinstein 结果与中间价基本一致。
   - 双方耐心不同（δ 不同）时，更有耐心的一方拿得更多，结果就偏离中间价。
   - AgenticPay 有 20 轮的硬截止。在完全信息、完全理性的简化假设下，最后一轮由买方先报价，卖方只能跟价或让谈判失败，按倒推法买方可以把价格压到卖方底价附近。真实的 LLM 并不会这样做，但这说明理论预测对"谁最后出价"这类协议细节很敏感。
3. **信息不完全时，100% 成交率本来就不是自然基准。** Myerson–Satterthwaite 定理表明：双方都有私人保留价、且双方保留价的可能范围有重叠时，不存在一个既满足激励相容、个人理性、预算平衡，又总能在有成交空间时成交的机制。Chatterjee–Samuelson 的双边报价模型中，均衡下只有在买方估值足够高于卖方成本时才成交。所以从理论上讲，即使双方都完全理性，也会有一部分本可以成交的谈判失败。
   - 需要说明：我们实验里的超时**不是**这种理论上的失败。所有超时的最终价差都只有 2.5–5，双方已经基本暴露了自己的底线，失败来自逐字重复自己上一条消息这类执行问题（主报告 3.4 节）。
4. **对买方来说，最优不是中间价。** BuyerScore 在价格等于卖方底价时最高。本任务要求"降低最终价格"，所以我们的目标是 BuyerScore，而不是 GlobalScore。我们的成交价都在 275 以上（A1-nod 平均 286.3），在这个区间里压价同时提高 BuyerScore 和 GlobalScore，两个目标暂时没有冲突。主报告 3.1 节已有说明。

### 1.3 可以做的扩展

- 在报告中同时给出几种理论基准（对称纳什解、不同 δ 下的 Rubinstein 解），而不是只用中间价评判"公平"。
- 设计一组让双方"耐心"不同的实验（例如在 prompt 中告诉一方有时间压力），看 LLM 的成交价是否按理论预测的方向移动。论文 Table 5 的 "Busy Professional" 人格已经部分涉及这一点，但没有和理论对比。

## 2. 多方市场的剩余：论文沿用 1v1 公式，只计一对

### 2.1 论文是否涉及

论文 §3 写道 "Negotiation outcomes are evaluated based on deal feasibility, efficiency, and welfare"，但 Algorithm 1 只有一个 1v1 公式（成交价 p、买方上限 pmax、卖方底价 pmin）。论文没有说明多方任务的分数怎么算。

代码中是这样实现的（以 `envs/multi_buyer_multi_seller/Task1_parallel_two_buyer_two_seller_negotiation.py` 为例，其他多方任务相同）：

| 代码位置 | 做了什么 |
|---|---|
| L380–401 | 同一轮里如果有多对达成一致，选 (买方上限 − 价格) + (价格 − 卖方底价) 最大的那一对，记为 `selected_buyer` / `selected_seller` |
| L412–413 | **只要有一对成交，整局立即结束**（`terminated = True`），其他买家和卖家不再交易 |
| L1022–1044、L1108–1145 | 分数只用被选中那一对的上限和底价计算议价区间 Z 和 Q，与 1v1 完全相同 |

三买三卖任务（`Task2_parallel_three_buyer_three_seller_negotiation.py` L506–536）也是同样的逻辑。

### 2.2 我们的分析：三个例子

下面的分数按 Algorithm 1、第 1 轮成交计算（D=30, W=55, E=15）。

**例 1：竞争结果被判低分。** 两个买家，上限分别为 350 和 300；一个卖家，底价 200。按拍卖理论（英式拍卖、私人价值），出价高的买家胜出，价格接近第二高的出价，即约 300。

| 成交价 | Q | GlobalScore |
|---|---|---|
| 275（这一对的中间价） | 1.000 | 100.0 |
| 300（竞争预测） | 0.889 | 93.9 |
| 310 | 0.782 | 88.0 |

竞争市场里卖家拿走大部分剩余是正常结果，但 GlobalScore 会把它判为"不够平衡"。

**例 2：低效率的匹配得满分。** 同样的市场，如果卖家把东西以 250 卖给上限 300 的买家：这一对的议价区间是 200–300，250 正好是中间价，Q = 1，GlobalScore = 100，和最有效率的匹配得分一样。但实际实现的总剩余是 100，而卖给上限 350 的买家可以实现 150。指标看不出这 50 的损失。

**例 3：一局只能成交一笔。** 两买两卖：买家上限 350、300，卖家底价 200、250，同一种商品。
- 两笔交易都可以互利（例如 350 的买家对 250 的卖家、300 的买家对 200 的卖家），市场最大总剩余为 (350 + 300) − (200 + 250) = 200。
- 竞争均衡价格在 250–300 之间：这个价格下两个买家都愿意买，两个卖家都愿意卖。
- 但论文版代码在第一笔成交后就结束，最多实现一笔交易，总剩余最多 150（75%）。剩下的那笔交易永远不会发生，指标也不会记录这部分损失。

### 2.3 这对论文结论意味着什么

- 论文 Table 2 显示参与方越多 GlobalScore 越高。由于指标只看一对、且越接近这一对的中间价得分越高，这个趋势**不能直接解释为市场效率更高**。可能只是参与方越多，越容易找到一对谈出接近中间价的组合。
- 这不是说论文的结果错了，而是论文的指标衡量的是"成交那一对谈得是否平衡"，而不是"市场整体是否有效率"。§3 中提到的 welfare（福利）在多方任务里并没有被完整度量。

### 2.4 可以做的扩展

见第 5 节。

## 3. A1 比 A0 好，能说是 prompt 带来的吗

### 3.1 论文是否涉及

没有讨论。论文 §5.1 写道 "All agents use deterministic decoding with temperature 0 and random seed 0 … Each task instance is executed once per model"。论文在人格实验（Table 5）、交叉对战（Table 4）中直接把分数差异归因于人格或模型，没有重复实验、置信区间或显著性检验，也没有讨论 prompt 措辞的敏感性。

### 3.2 我们能说什么

我们的实验是受控的干预实验，不是观察数据：

- A0_personas 与 A1 之间只改了买方 prompt；模型文件、卖方 prompt、人物资料、种子 0–9、成交规则、采样参数都相同。
- 运行代码在基准实验（commit `3289dd2`）之后只增加了两项功能：读取人物资料文件，以及一个可选的 llama.cpp prompt 缓存（只影响速度）。规则、prompt 拼接和采样代码没有改动（`git diff 3289dd2 HEAD` 可核对）。

所以在这个设定里，可以说**"这次 prompt 改动导致了成交率和价格的差异"**，偶然性由检验衡量（A1 对 A0_personas 成交率 p = 0.0055；A1 对论文基线成交价 p = 0.012）。

### 3.3 不能说什么

| 说法 | 为什么不能这样说 |
|---|---|
| "是某一条策略（如中间价规则）起了作用" | prompt 是整体改动，多条规则和措辞一起变了，分不清是哪一句。A1-nod 说明删掉一句从未触发的话，成交率也从 8/10 变到 10/10，措辞本身就有影响 |
| "对其他模型、其他卖方也有效" | 只在 Qwen3-4B（Q8）对论文默认卖方的情况下测过。默认卖方容易照抄买方的中间价，这对 A1 有利（主报告 5.1 第 5 点） |
| "A1-nod 比 A1 好" | 10/10 对 8/10，p = 0.47。见下面的样本量计算 |
| "同一个种子下 A0 和 A1 可以配对比较" | 不行。prompt 不同，模型每一步的概率分布就不同，同一个种子产生的随机序列对应的是完全不同的对话，不构成配对 |
| "结果在新的种子上也会一样好" | v1→v5 的每一次修改主要依据种子 0 的试运行结果，存在对测试集过拟合的风险。种子 0 也包含在最终的 10 次运行里 |

### 3.4 样本量：10 次能看出多大的差异

用模拟估计双侧检验（α = 0.05）的检出概率（统计功效）。成交率用 Fisher 精确检验，每种情况模拟 4000 次；价格用 Mann–Whitney 检验，并假设价格服从正态分布（均值和标准差取自实际结果）。本文所有计算（功效、评分例子、Rubinstein 基准、耗时表）的代码见 `experiments/bezos_graham/supplementary_calcs.py`，固定随机种子，可复现。

| 比较 | 每组 10 次 | 20 次 | 30 次 | 50 次 |
|---|---|---|---|---|
| 成交率 80% 对 100%（如 A1 对 A1-nod） | 0.04 | 0.38 | 0.58 | 0.95 |
| 成交率 60% 对 100%（如 A2 对 A1-nod） | 0.36 | 0.94 | 1.00 | 1.00 |
| 成交率 30% 对 80%（如基线对 A1） | 0.42 | 0.85 | 0.97 | 1.00 |
| 成交率 10% 对 80%（如 A0_personas 对 A1） | 0.85 | 1.00 | 1.00 | 1.00 |

- 每组 10 次只能可靠地看出"10% 对 80%"这种很大的差异。
- A1 和 A1-nod 之间（80% 对 100%）每组需要约 50 次才有 95% 的把握看出差异。
- 价格方面，A1（289.7）与 A1-nod（286.3）相差约 3.4，每组 300 次的功效也只有约 0.77，实际上可以视为没有差异。A2 与 A1 相差约 11，每组 20 次的功效约 0.32。

### 3.5 可以做的扩展

1. **析因消融**：把 A1 拆成几个模块（消息格式、首次报价、接受规则、中间价规则、让步幅度），逐个打开或关闭，估计每个模块的效果。
2. **更多种子，并把"调参种子"和"评估种子"分开**：例如只用种子 0–4 调 prompt，用 100–149 做最终评估。
3. **换对手和模型**：用更强硬的卖方 prompt、更大的模型扮演卖方，检验策略是否依赖默认卖方的习惯。
4. **措辞扰动**：对同一策略写 3–5 种措辞不同但含义相同的版本，看结果的波动有多大。这能区分"策略的效果"和"措辞的效果"。
5. **事先登记分析计划**：在跑正式实验前写下要比较的组、指标和检验方法，避免看到结果后再挑比较。

## 4. 算力：CPU 不能替代 GPU，以及代码的可扩展性

### 4.1 论文是否涉及

论文 §5.1："For open-source models, we perform inference using 4 NVIDIA A800 GPUs"，每次回复最多生成 1024 个 token。论文强调框架 "scalable"、支持 vLLM、SGLang 和云端 API，但没有讨论算力受限、量化或 CPU 运行对结果的影响。

### 4.2 我们的情况

本实验只有 CPU 和 16 GB 内存，用 Q8_0 量化的 GGUF 文件运行（主报告 1.3 节）。各组 10 次运行的耗时（来自 `results/*/runs.csv` 的 `elapsed_s`）：

| 组 | 单次最短 | 单次最长 | 平均 | 10 次合计 |
|---|---|---|---|---|
| A0_paper_default | 2.3 分钟 | 97 分钟 | 60 分钟 | 10.1 小时 |
| A0_personas | 7.4 分钟 | 111 分钟 | 75 分钟 | 12.5 小时 |
| A1 | 6.6 分钟 | 94 分钟 | 26 分钟 | 4.3 小时 |
| A2 | 6.9 分钟 | 96 分钟 | 44 分钟 | 7.3 小时 |
| A1-nod | 4.1 分钟 | 12.8 分钟 | 9 分钟 | 1.5 小时 |

50 次正式运行共约 36 小时，超时的运行（20 轮）单次要 70–111 分钟。

算力限制带来了以下影响：

1. **样本量小**：每组只能跑 10 次，见 3.4 节。
2. **模型小、且经过量化**：论文最小的开源模型是 Llama-3.1-8B，我们用的是 4B 的 Q8 版本。Q8 与原版接近但不完全相同。
3. **生成长度更短**：论文每次最多 1024 个 token，我们设为 300，以控制运行时间。我们的买方 prompt 要求每条消息少于 80 词，所以影响应该不大，但对论文默认 prompt 的基线组来说，这是一处与论文不同的设置，主报告 1.4 节没有单独列出。
4. **迭代成本高**：每改一次 prompt 只能先跑 1 次试验，这是 3.3 节"对测试集过拟合"风险的直接原因。
5. **没有做温度 0 的论文式对照**：理论上可以加一组 temperature 0 来和论文设置对齐，但只能得到 1 条对话，信息量很少，在算力有限时我们没有做。

### 4.3 代码的可扩展性

| 方面 | 现状 | 有 GPU 或想扩展时 |
|---|---|---|
| 推理后端 | 已支持 `mock` / `hf`（transformers）/ `gguf`（llama.cpp）/ `vllm` | 有 NVIDIA GPU 时用 `--backend vllm`（Linux）或 `--backend hf --device cuda` 加载原版权重，可直接换更大的模型 |
| 实验参数 | 轮数、初始要价、种子、温度、生成长度、买卖方模板、人物资料均可通过命令行修改 | 买方上限 350、卖方底价 200 目前写在 `exp_config.py` 中，需要加命令行参数才能做保留价的敏感性实验 |
| 人物资料 | `persona_pipeline.py` 是通用流程（Wikidata 查询 + 文件正则 + 本地模型抽取 + 原文校验） | 换人物只需修改查询目标和来源列表 |
| 机制分析 | `analyze_closing.py` 只针对 1v1 | 多方任务需要按"每一对"统计 |
| 多方任务 | `episode.py` 只驱动 1v1 的 Task1 环境 | 需要：(1) 驱动多方环境的循环（上游 `examples/` 下每类任务都有示例）；(2) 为每个买家、卖家分别设置 prompt 和人物资料；(3) 第 5 节的市场层面指标 |

## 5. 多买多卖：分析框架应从 1v1 升级到博弈论模型

### 5.1 论文是否涉及

- 论文相关工作（§2）引用了 Chatterjee & Samuelson（1983）、Myerson & Satterthwaite（1983）、Rubinstein（1985）等经典文献，但把它们作为对比对象："These models typically assume agents interact through scalar bids or utilities … such formulations abstract away the role of language"。分析部分没有使用这些模型做基准。
- 论文贡献中写到 "We formalize language-mediated buyer–seller negotiation as a multi-agent game with private reservation values"，但没有求解或引用这个博弈的均衡。
- 对 Table 2（参与方越多分数越高），论文 §5.3 的解释是："can be attributed to increased market liquidity: agents have more opportunities to find compatible trading partners, and the presence of alternatives encourages more reasonable offers and faster convergence." 这是一个假设，论文没有设计实验验证。

### 5.2 我们的分析

1v1 的分析逻辑是"一对买卖双方 + 一个议价区间 + 离中间价多远"。多方市场有 1v1 没有的问题：

| 问题 | 1v1 中 | 多方市场中 |
|---|---|---|
| 谁和谁成交（配置） | 只有一种可能 | 有多种匹配方式，效率可以差很多（第 2 节例 2） |
| 成交几笔 | 0 或 1 | 可以有多笔，总剩余取决于成交了几笔（第 2 节例 3） |
| 价格的理论基准 | 议价解（纳什、Rubinstein） | 竞争均衡价格、拍卖价格（第 2 节例 1） |
| 外部选择 | 只有"不成交" | 可以转向其他对手，外部选择决定议价力 |
| 新的策略行为 | 无 | 共谋、虚张声势称"有别的报价"、在多个谈判间压价 |

所以多方任务需要的不是把 1v1 公式套用到最后那一对上，而是一套市场层面的分析框架。

### 5.3 建议的指标和基准

| 指标或基准 | 定义 | 回答的问题 |
|---|---|---|
| 配置效率 | 实际实现的总剩余 ÷ 市场最大总剩余（最大值用最优分配求出） | 市场是否把东西交给了最看重它的人、由成本最低的人提供 |
| 成交笔数比例 | 实际成交笔数 ÷ 有效率的成交笔数 | 互利的交易是否都发生了 |
| 竞争均衡价格区间 | 单一商品、每人最多买卖一件时，把买家上限从高到低、卖家底价从低到高排序，均衡价格在供需曲线交点的区间内 | 成交价是否落在竞争市场的预测范围内 |
| 拍卖基准（一卖多买） | 英式拍卖下价格约为第二高的买家上限；一买多卖时约为第二低的卖家底价 | 竞争是否真的把价格推向理论值 |
| 稳定性（Shapley–Shubik 分配博弈） | 检查是否存在"阻挠对"：一对没有成交的买卖双方，彼此成交能让两人都更好 | 结果是否稳定，是否有人有动机偏离 |
| 剩余分配 | 买方总剩余、卖方总剩余，与竞争均衡下的分配对比 | 谁在竞争中获益 |
| 共谋检测 | 同侧代理之间的价格是否同步、是否出现明显高于竞争基准的价格 | LLM 代理是否会自发共谋（论文引用了 Agrawal et al. 2025 关于 LLM 在双边拍卖中共谋的研究，但自己没有检测） |

### 5.4 建议的实验

1. **检验"市场流动性"解释**：固定一个买家和一个卖家的保留价，逐步增加竞争对手的数量（1、2、3 个），看成交价是否向竞争均衡或拍卖基准移动，成交速度是否加快。如果流动性解释成立，价格应该朝理论方向移动；如果只是"更容易凑出一对中间价"，价格不会系统性移动。
2. **允许多笔成交**：修改环境，让已成交的一对退出，其余参与方继续谈，直到无人愿意成交或达到轮数上限。这样才能度量配置效率和成交笔数。
3. **与人类实验对比**：实验经济学中有大量双边拍卖、多方议价的人类实验数据（如 Vernon Smith 关于双边拍卖收敛到竞争均衡的经典实验），可以作为 LLM 行为的参照。
4. **本任务的多方版本**：例如加入第二个潜在买家（另一位有意收购报纸的投资者），看"Bezos"的成交价和成交率如何变化，以及 A1 这类策略在有竞争者时是否仍然有效。

## 6. 小结

| 问题 | 论文 | 本文的补充 |
|---|---|---|
| 中间价最优 | 只说明指标在平分时最高 | 指出 Q 是归一化的纳什乘积，中间价是价值判断；理论预测随模型和协议变化；信息不完全时 100% 成交率不是自然基准 |
| 多方剩余 | 沿用 1v1 公式，只计一对，第一笔成交即结束 | 用三个例子说明指标可能把竞争结果判低分、把低效匹配判满分、忽略未发生的交易 |
| 因果解释 | 没有讨论，单次运行 | 说明受控实验能支持的结论和不能支持的推广，并用功效计算说明 10 次样本能看出多大的差异 |
| 算力 | 4 张 A800，未讨论受限情况 | 量化 CPU 耗时，列出算力对样本量、模型、生成长度、迭代的影响，以及代码扩展需要补的模块 |
| 博弈论框架 | 只在相关工作中引用；"流动性"解释未验证 | 提出市场层面的指标、理论基准，以及检验"流动性"解释的实验设计 |

这些问题都不影响主报告在本任务范围内的结论（1 买 1 卖、同一模型、只改买方 prompt），但如果要把这类实验推广到多方市场或用来分析真实交易，它们都需要先解决。
